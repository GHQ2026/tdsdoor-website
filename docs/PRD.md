## 一、问题陈述

安徽拓达昇门业科技有限公司（合肥，2021年成立，注册资金500万）是一家工业门产品与服务的 B2B 制造企业，已服务比亚迪、格力、美的、TCL、国轩高科、可口可乐、极狐、金鹏控股等 18 家企业客户，但目前缺少一个能承载其"智能工业门专家"定位的线上门户。

当前痛点：
1. **无正式官网或官网过于简陋**，B 端采购方（工厂基建负责人、总包方、工程公司）在搜索"合肥 工业快速门厂家"等关键词时找不到可信的着陆页，线上获客通道缺失。
2. **信任资产无处沉淀**：18 家知名客户合作案例、产品资质、公司实力无法系统性展示，采购方无法在 3-5 秒内判断"这家公司能解决什么问题、凭什么信"。
3. **内容更新依赖技术人员**：新闻、案例、产品信息发布需要懂代码的人改页面，运营效率低，上线后无法自主更新。

B2B 工业采购调研结论（联网调研，2026-08）：工业门采购决策周期长（1-6 个月）、决策链复杂（使用部门提出 → 设备/基建部门筛选 → 采购比价 → 管理层审批），采购方平均对比 6 家以上供应商后才决策。采购方 43% 的采购行为从搜索官网开始，67% 的决策时间偏好无销售介入的自助浏览。官网的核心任务不是"在线成交"，而是**获取有效询盘 + 建立采购信任**。

## 二、目标用户

### 主要用户画像 1：B 端采购决策人（占预期流量 60%）
- **身份**：制造业企业设备科/基建科负责人、工程总包方项目经理、厂房设计师
- **年龄**：30-50 岁，机械/土建背景，实用主义
- **场景**：新建厂房或产线改造需要工业门（快速门/提升门/防爆门等），通过百度/搜索引擎搜"工业快速门厂家""防爆门 合肥"等词进入官网
- **决策关注点**：产品技术参数是否专业完整、有无同行业（汽车/家电/食品/化工）案例、厂家资质与生产实力、报价与响应速度
- **技术水平**：桌面为主（办公室场景），移动端为辅（厂区巡场、展会场景）
- **核心诉求**：快速找到适合自己工况的门型 → 查看参数与案例 → 低门槛发起询价（电话或表单）

### 主要用户画像 2：公司自有运营人员（后台用户）
- **身份**：拓达昇的行政/市场人员，非技术人员
- **场景**：上线后自主发布新闻动态、上传案例照片、维护产品信息与公司资料
- **核心诉求**：零代码、类微信公众号后台式的编辑体验，发布内容不需要找开发者

### 次要用户画像 3：合作伙伴与求职者（占预期流量 15%）
- **身份**：供应商、经销商、潜在求职者、媒体
- **诉求**：了解公司概况、规模、联系方式

### 次要用户画像 4：搜索引擎与生成式 AI（非人类用户，但影响获客）
- 2026 年趋势：采购方越来越多通过 AI 搜索（如文心一言、豆包、DeepSeek）获取供应商推荐。官网需要语义化 HTML、结构化数据（JSON-LD）、清晰的产品参数与 FAQ 内容，才能被 AI 引用。

### 3.3 竞品结论

1. 三家国内直接竞品的官网都是"电子型录"逻辑——重产品展示、弱询盘转化、弱场景匹配。我们的机会在于：**围绕采购决策路径组织内容**（按行业场景匹配门型 + 参数完整 + 案例佐证 + 低门槛询价），而不是简单做一个更漂亮的型录。
2. 国际标杆证明"高级感"来自：克制的视觉 + 真实数据 + 场景化内容，而非花哨动效。这与用户"仿华为/威得力式大厂风、不能低端廉价"的要求一致。
3. 差异化定位：**本地服务半径（合肥/安徽，24 小时响应）+ 18 家头部客户案例 + 场景化选型内容**。对华东制造企业采购方，"本地有厂、有人、有案例"是比价格更硬的信任点。

## 四、我们的差异化

用户为什么选拓达昇官网而不是竞品官网？（对采购方而言）

1. **首屏 3 秒讲清楚**：主标语「拓达昇·智能工业门专家」+ 核心产品场景图 + 关键数字（18 家合作客户、注册资金 500 万、深耕华东），不搞空洞的"品质第一"式文案。
2. **场景化产品导航**：6 个主打产品详情页均按"产品是什么 → 适用哪些工况 → 技术参数 → 相关案例 → 立即询价"的采购决策路径组织，而不是竞品的图片堆砌。
3. **案例即证据**：比亚迪/格力/美的/国轩高科等客户 Logo 墙 + 案例卡片（行业标签 + 应用产品 + 项目简述），直接回应采购方"你们做过我们这个行业吗"的第一问题。
4. **双通道询价**：电话直拨（移动端点击拨号 136 7551 2533）+ 精简表单（企业名称/联系人/需求简述 3 项起步，可选门型），覆盖不同决策阶段的采购方。
5. **上线后可持续运营**：CMS 后台让非技术人员自主更新内容，持续输出 SEO 内容，避免竞品"建完就死"的通病。

## 七、MVP 范围

**MVP 只做以下内容（P0，全部纳入本次建设）：**
1. 前台 6 栏目全站页面（含 6 个产品详情页 + 4 个分类列表页）
2. 双通道询价转化（表单邮件至 82257018@qq.com + 移动端电话直拨）
3. CMS 轻量后台（新闻/产品/案例/公司信息/媒体库/表单记录 6 大模块）
4. SEO 基础（meta/OG/sitemap/robots.txt/JSON-LD/语义化 HTML/301 规则预留）
5. 响应式适配（桌面 + 移动端）
6. 高德地图嵌入 + 询价表单

**P1（本次建设尽力包含，资源不足时降级为 Backlog）：**
- 案例行业筛选、新闻分类筛选
- 首页数据信任带数字后台可配置
- 数据埋点采集（见第十节，若架构允许 P1 完成，否则上线后补）

**明确不做（Out-of-Scope）：**

## 十、数据埋点方案（PRD 必含）

MVP 必埋事件（不埋 = 上线后无法验证"官网能否带来询盘"这一核心假设）：

| 事件类别 | 必埋事件 | 说明 |
|----------|----------|------|
| 获客 | page_view（含来源 referrer） | 采购方从哪来（搜索/直接/竞品词） |
| 激活 | first_inquiry_view（首次进入询价表单区） | 用户是否找到了询价入口 |
| 转化 | inquiry_form_submit（区分来源页面：产品页/联系页） | 询盘转化漏斗核心事件 |
| 转化 | phone_click | 移动端电话直拨点击——工业门行业电话询盘占比高，此事件与表单同等重要 |
| 留存 | product_detail_view（含产品 ID） | 哪个产品最受关注，指导内容运营 |
| 留存 | case_detail_view、news_detail_view | 内容营销效果 |
| 异常 | form_submit_error、page_error | 表单提交失败需可追溯 |

实现要求：
- 轻量方案：自建 trackEvent() 封装或接入免费统计（百度统计/Umami），由架构师选型
- 事件命名规范：{对象}_{动作}，如 inquiry_form_submit、phone_click
- 每事件附带 user_id（匿名 ID）、timestamp、device、page_url、version
- 不采集隐私数据：不上报表单内容明文、不存原始 IP

- When 移动端用户点击页面上的电话号码, Then 直接唤起拨号界面（tel: 链接）。

## 十二、边界条件与异常状态

- **空状态**：新闻/案例/分类产品列表为空时显示引导文案（如「案例整理中，欢迎电话咨询」）+ 电话入口，不显示空白页面或报错。
- **占位内容标注**：建设期所有占位文案（案例、资质、参数）需在交接文档中列清单，供用户上线后逐一核对替换——**此清单纳入审核节点交付物**。
- **表单垃圾提交**：同一 IP 高频提交触发速率限制（如 1 分钟 ≤3 次），超限提示稍后再试。
- **图片缺失**：后台未上传封面时使用统一的行业风格默认图，不出现破图。
- **地图加载失败**：高德地图组件加载失败时降级为纯文本地址 + 「跳转高德地图」链接。
- **权限边界**：后台单管理员 MVP 阶段无角色区分，但删除操作全部二次确认。
