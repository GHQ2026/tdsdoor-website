# ADR-007: 使用 Tailwind CSS 4 作为样式方案

## Status: Accepted (2026-08-28)

## Background

设计系统为"浅色简约高级"，需要将设计令牌（颜色/字体/间距/圆角/阴影）工程化落地，且不能向静态页面引入运行时开销。备选：手写 CSS、CSS Modules、UnoCSS。

## Decision

选用 Tailwind CSS 4（^4.1），设计令牌集中定义在 global.css 的 Tailwind 主题层（@theme），组件以原子类组合样式。

理由：
- 令牌即代码：设计系统的颜色/间距收敛为单一来源，设计师交付的令牌表可直接翻译进主题层，组件内禁止散落魔法值（已写入代码组织硬规则）。
- 构建期生成最小化 CSS，无运行时开销，与 Astro 零 JS 理念一致。
- 工具类即约束：浅色简约风格下样式一致性靠约定而非自觉，Tailwind 的约束性最强。
- 手写 CSS 在多人/多 AI 协作下必然风格漂移；UnoCSS 生态与文档弱于 Tailwind。

## Consequences

- 正面：样式与设计系统一一对应，改令牌全站生效；产物 CSS 体积极小（预计 <30KB gzip 前）。
- 负面：类名较长，需要规范（同一组件类名排序一致）；对不熟悉者有学习成本（开发由 AI 辅助执行，影响有限）。
- 约束：禁止紫色到粉色渐变方案（P0 规则）；设计令牌文件由设计师产出的设计系统文档驱动，见 UI Spec。
